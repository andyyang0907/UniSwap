版本：1.0  
产品名称：UniSwap  
Slogan：A smarter way to exchange on campus.  
产品定位：面向大学生的校园闲置资源流转平台，支持二手交易、免费赠送与物品交换。

# 二、背景与资料

## 2.1 产品背景

UniSwap 是一个以大学校园为边界的闲置资源流转平台。它不是传统电商平台的缩小版，重点是让同校学生以轻量、可信、低成本的方式处理闲置物品。

核心场景：
1. 二手交易：学生发布闲置物品，其他学生表达购买意向。
2. 免费赠送：将仍有使用价值的物品免费转给有需要的同学。
3. 物品交换：双方以物换物，协商交换条件。
4. 校园当面交付：优先选择校园公共地点和预约时间，减少复杂物流。

## 2.2 第一版产品边界

第一版重点完成完整的本地交互闭环：
- 浏览、搜索、筛选商品。
- 查看商品详情与卖家资料。
- 发布二手、赠送或交换物品。
- 收藏商品。
- 创建交易意向。
- 选择交付地点与预约时间。
- 查看消息、交易状态和个人发布记录。

第一版不接入真实支付，不做复杂实名认证，不做云端即时通讯，不做物流系统。数据先采用本地持久化方案，结构应便于未来替换为后端 API。

## 2.3 品牌与视觉方向

关键词：高级、极简、温暖、可信、校园感、轻科技。

视觉原则：
- 参考 Apple 产品的克制、清晰、精致感，但不要直接复制 Apple 界面。
- 以暖白色作为大面积底色，深森林绿作为品牌主色。
- 商品图片应成为内容主体，界面不要被装饰元素抢戏。
- 留白充足，信息层级明确，卡片轻盈。
- 图标统一使用简洁线性风格。
- 避免廉价渐变、强烈投影、荧光色、蓝色科技风、密集标签和传统电商促销感。

## 2.4 颜色规范

| 用途 | 色值 |
|---|---|
| 品牌主色 / Primary | `#174D3A` |
| 辅助绿 / Secondary | `#75A88A` |
| 浅绿背景 | `#EAF1EB` |
| 页面背景 | `#F8F8F5` |
| 卡片背景 | `#FFFFFF` |
| 主文字 | `#202522` |
| 次级文字 | `#858B86` |
| 分割线 | `#E8EBE6` |
| 提醒暖橙（少量） | `#E5A85B` |
| 错误状态 | `#C65B52` |

颜色使用比例建议：暖白与白色约 80%，绿色约 15%，其他强调色不超过 5%。

## 2.5 字体与图标

- 优先使用系统字体，中文使用系统默认中文字体，英文与数字保持清晰。
- 页面标题建议 24–30sp，模块标题 17–20sp，正文 14–16sp，辅助信息 12–13sp。
- 图标使用统一线性图标体系；同一含义不可混用不同风格。
- 圆角建议：小控件 10–12dp，卡片 16–20dp，大型底部面板 24–28dp。
- 页面左右安全边距建议 20dp；卡片间距 12–16dp。

## 2.6 Logo 资产

使用 `assets/uniswap_logo.svg` 作为品牌标志，`assets/uniswap_app_icon.svg` 作为应用图标参考。不得自行重绘或替换。图形寓意为两条相向流动的箭头，表达资源循环、交换与连接；不使用购物车图形。

# 三、任务

## 3.1 应用总体结构

采用底部五栏主导航：

1. Home：首页
2. Discover：发现 / 搜索
3. Publish：发布（中间主按钮，视觉权重最高）
4. Messages：消息
5. Profile：个人中心

要求：
- 五个 Tab 各自保留导航栈与滚动位置。
- 切换 Tab 不应无故重置页面。
- Publish 使用突出但克制的圆形或胶囊式主按钮，主色填充。
- 当前 Tab 有平滑的选中反馈，不要使用夸张弹跳。

## 3.2 页面清单与布局要求

### A. Home 首页

页面结构从上到下：
1. 顶部品牌区：UniSwap 字标、校园/位置提示、通知入口。
2. 搜索入口：圆角搜索框，点击进入独立搜索页面。
3. 三个交易方式快捷入口：Buy（二手）、Give（赠送）、Swap（交换）。
4. 分类快捷区：数码、教材、生活用品、运动、其他。
5. 推荐商品区：双列商品卡片，图片优先，价格/免费/交换状态清晰。
6. 可选的校园精选或近期上新区块。

商品卡片：
- 图片采用接近 4:5 的比例，圆角 14–16dp。
- 图片下方依次展示标题、价格或 FREE / SWAP 标签、轻量卖家信息。
- 收藏按钮覆盖在图片角落，点击有缩放反馈。
- 不显示虚构销量、评价或促销数据。

### B. Discover 发现页

- 顶部搜索框，支持输入、清空、提交。
- 搜索结果页显示关键词与结果数量（仅在数据真实可得时显示数量）。
- 筛选项：交易方式、分类、价格区间、发布时间、交付方式。
- 排序项：最新发布、价格从低到高、价格从高到低。
- 筛选面板采用底部模态面板，支持重置与应用。
- 空结果页面提供清晰的空状态插画/图标和清除筛选操作。

### C. Product Detail 商品详情页

这是全 App 的核心展示页面，必须精致完成。

布局：
1. 顶部大图区域，可左右滑动查看多张图片。
2. 返回与收藏按钮浮于图片上方，保证可读性。
3. 商品价格 / FREE / SWAP 状态。
4. 商品标题、发布时间、分类与物品状态。
5. 商品描述，支持展开 / 收起。
6. 交付方式与推荐校园公共地点。
7. 卖家信息卡片：头像、昵称、信誉摘要、进入卖家主页。
8. 底部固定操作区：根据商品类型显示“联系卖家 / 表达意向”等主操作。

详情页要有明显的视觉呼吸感，避免堆满边框和标签。

### D. Publish 发布流程

采用分步骤流程，避免一次性长表单压迫用户。

步骤：
1. 选择发布类型：二手出售 / 免费赠送 / 物品交换。
2. 添加图片：支持多张图片、预览、删除、调整顺序。
3. 填写基本信息：标题、分类、物品状态、描述。
4. 根据类型显示差异字段：
   - 出售：价格。
   - 赠送：无需价格。
   - 交换：期望交换物品或交换说明。
5. 设置交付方式：校园当面交付优先，可填写可选地点与时间说明。
6. 预览发布内容。
7. 发布成功页，提供查看详情与继续浏览入口。

交互：
- 顶部显示步骤进度。
- 下一步按钮在必填项不完整时禁用，并给出明确提示。
- 返回上一步保留已填写内容。
- 图片选择、表单校验、预览和发布成功都必须是真实可操作的流程。

### E. Messages 消息页

- 消息列表展示头像、昵称、最近消息、时间、未读状态。
- 聊天详情页采用常见左右气泡布局，但视觉保持克制。
- 消息输入栏固定在底部，键盘弹出时布局正确避让。
- 第一版可以使用本地模拟会话数据，不接入真实云端通讯。
- 提供交易意向卡片与预约确认卡片，可进入对应交易详情。

### F. Profile 个人中心

顶部个人资料卡片：头像、昵称、校园身份展示占位、个人简介。

功能入口：
- 我的发布
- 我的收藏
- 我的交易
- 浏览记录（可作为后续扩展）
- 设置

“我的发布”支持查看、编辑、下架；“我的收藏”支持取消收藏；“我的交易”展示交易状态与预约信息。

### G. 其他子页面

- 搜索页面
- 筛选面板
- 全屏图片预览
- 卖家主页
- 交易意向页
- 预约确认页
- 交易详情页
- 设置页
- 空状态 / 错误状态 / 加载状态

## 3.3 核心业务交互

### 交易意向
从商品详情进入，根据类型展示不同选项：
- 出售：表达购买意向。
- 赠送：申请领取，并填写简短说明。
- 交换：提出交换物品或交换条件。

### 预约确认
用户选择校园公共地点、日期与时间段，提交预约请求。页面明确展示双方、商品、地点、时间和当前状态。第一版不做真实地图导航与支付。

### 交易状态
建议状态：
- 待回应
- 待确认预约
- 已预约
- 交易进行中
- 已完成
- 已取消

状态变更必须有清楚的反馈，不能只改变按钮文字。

## 3.4 动画与交互设计清单

动画目标：自然、轻盈、有连续性。动画是信息反馈和空间关系的表达，不是装饰。以下均为实现要求，可根据 Flutter 技术条件选用对应组件，但不得删除核心动效关系。

### 页面转场与共享元素

1. Home 商品卡片 → 商品详情：使用 `Hero` 共享商品图片；详情内容配合 `FadeTransition` / `SlideTransition` 依次出现；返回时反向连续。
2. Discover 商品卡片 → 商品详情：复用相同 Hero 规则。
3. 商品详情 → 全屏图片预览：图片使用 `Hero` 放大，背景渐变淡入；关闭时反向还原。
4. 商品详情 → 卖家主页：头像使用 `Hero` 共享元素过渡。
5. 商品详情 → 交易意向页：使用底部上滑的模态路由，可结合 `PageRouteBuilder`。
6. 交易意向 → 预约确认：使用共享内容/卡片的连续过渡，建议 `OpenContainer` 风格或自定义 `PageRouteBuilder`。
7. Publish → 商品预览：封面图片 Hero 过渡，标题、价格、描述分段淡入。
8. 搜索入口 → 搜索页：搜索框采用共享元素或连续变形效果，进入后自动聚焦输入框。
9. Messages 列表 → 聊天详情：轻量横向滑入，避免过度位移。
10. Profile → 我的发布 / 收藏 / 交易：轻量横向或淡入转场，保持方向一致。

### 页面内动效

11. 首页商品列表：首屏卡片轻量错峰出现，使用 `Staggered Animation`；滚动加载的新内容避免重复大幅动画。
12. 商品图片轮播：横向拖动跟手，页码指示器平滑更新。
13. 商品描述展开：使用 `AnimatedSize`，避免突然跳变。
14. 筛选面板：底部滑入 + 背景淡化；筛选分组逐项出现。
15. 发布步骤：步骤内容采用 `AnimatedSwitcher` 或 `PageTransitionSwitcher` 风格过渡；步骤进度条平滑推进。
16. 图片添加：新图片缩放淡入；删除时缩小淡出；拖动排序时其他图片平滑让位。
17. 预约成功：勾选图标 `ScaleTransition` + 轻微弹性曲线，内容淡入。
18. 聊天消息：新消息轻量淡入上移；发送按钮有按压反馈；消息列表保持滚动稳定。
19. 收藏按钮：点击时 `ScaleTransition`，图标通过 `AnimatedSwitcher` 切换填充状态。
20. 交易状态变化：状态标签颜色与文字平滑过渡，配合轻量提示。
21. 底部导航：图标/文字颜色与尺寸平滑变化；Publish 主按钮按压缩放。
22. 按钮按压：使用 `AnimatedScale` 或 `InkWell` 的轻量反馈。
23. 卡片按压：短暂缩放至约 0.98，再恢复；不产生明显弹跳。
24. 下拉刷新：采用简洁品牌色进度指示。
25. 空状态：图标轻微淡入或上移，不做循环晃动。
26. 加载状态：骨架屏 Shimmer（低对比度、避免高频闪烁）。
27. Toast / SnackBar：从底部轻量进入，显示后自然退出。
28. 页面滚动时顶部区域可做轻微透明度/高度变化，但不能影响内容可读性。

### 动画技术建议

优先考虑：
- `Hero`
- `PageRouteBuilder`
- `AnimatedSwitcher`
- `AnimatedContainer`
- `AnimatedSize`
- `AnimatedOpacity`
- `AnimatedAlign`
- `AnimatedPositioned`
- `AnimatedScale`
- `FadeTransition`
- `SlideTransition`
- `ScaleTransition`
- `SizeTransition`
- `RotationTransition`
- `AnimatedList`
- `AnimationController`
- `Tween`
- `CurvedAnimation`
- `AnimatedBuilder`
- `Interval`
- `ScrollController`

建议时长：
- 按压与微交互：120–220ms
- 普通页面转场：250–380ms
- Hero 共享元素：350–500ms
- 分阶段内容入场：400–700ms
- 成功反馈：350–600ms

曲线建议：`Curves.easeOutCubic`、`Curves.easeInOutCubic`、`Curves.fastOutSlowIn`；只有确认成功等少数反馈可使用克制的 `Curves.elasticOut`。

### 动画工程约束

- Hero tag 必须按商品 ID / 用户 ID 唯一生成，避免列表中多个相同商品图片冲突。
- 正向与反向转场都要正确。
- 页面快速连续点击时不能重复 push 相同路由。
- `AnimationController` 必须正确 dispose。
- 页面销毁后不得继续 setState。
- 动画不能阻塞滚动、输入和图片加载。
- 尊重系统减少动态效果设置；必要时降低或关闭非必要动效。
- 不要给每个元素都加动画；优先保证主视觉、关键状态和交互反馈。

# 四、边界和约束

## 4.1 不得擅自修改

- 产品名称 UniSwap 与 Slogan。
- 三种交易方式：二手出售、免费赠送、物品交换。
- 五栏底部导航结构。
- 深森林绿 + 暖白的品牌视觉方向。
- 页面核心信息层级与关键交互流程。
- 本文明确指定的 Hero 与页面转场关系。

## 4.2 第一版暂不开发

- 真实支付、钱包、退款。
- 复杂实名认证和学生证 OCR。
- 云端即时通讯、推送服务。
- 物流、快递、自动运费计算。
- 复杂推荐算法、广告系统、会员体系。
- 公开社交动态、关注关系、评论社区。

可以预留接口，但不要提前实现成复杂系统。

## 4.3 技术实现要求

- 使用 Flutter + Dart。
- 采用清晰、可维护的目录结构；UI、业务逻辑、数据模型和数据存储适当分离。
- 使用本地持久化保存商品、收藏、个人资料、会话和交易流程数据。
- 图片选择与本地图片展示必须真实可用。
- 数据模型要区分出售、赠送、交换类型。
- 组件可复用，但避免过度抽象。
- 适配 iPhone 常见尺寸与 Android 常见尺寸，处理安全区、键盘和滚动。
- 页面不能只有静态 UI；所有可见按钮都必须有对应行为。
- 不得用无意义的随机数据伪装真实业务状态。
- 图片缺失时提供统一占位图。
- 处理空列表、无搜索结果、加载中、失败、表单校验等状态。

## 4.4 交付与开发节奏

按阶段开发，每阶段完成后先运行检查，不要一次性堆出大量未经验证的代码。

阶段 1：工程骨架、主题系统、Logo、底部导航。  
阶段 2：首页、商品卡片、商品详情、Hero 动画。  
阶段 3：Discover、搜索、筛选。  
阶段 4：发布流程、图片选择、预览与发布成功。  
阶段 5：交易意向、预约确认、交易详情。  
阶段 6：消息页、聊天详情、个人中心。  
阶段 7：补齐动画、空状态、错误状态、适配与测试。

每阶段交付：
- 可运行代码。
- 本阶段完成的页面与交互列表。
- 尚未完成项与已知问题。
- 运行/测试结果。

开始前先检查当前项目结构与 Flutter 环境。若已有代码，先理解再修改，不要直接覆盖项目。涉及依赖时说明用途。遇到本设计文档未定义且会影响产品体验的决策，先向需求方提问。
